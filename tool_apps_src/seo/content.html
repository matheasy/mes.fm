      Free SEO checker: see your page the way a search engine does

      Type the address of any web page and get an on-page SEO audit in plain English: the title and meta description (with a Google-style preview that cuts them where Google would), the headings, canonical tag, robots rules in the page and in robots.txt, whether the page is in the sitemap, Open Graph and X (Twitter) cards, structured data (JSON-LD), image alt text, internal and external links, the mobile viewport, HTTPS, compression and how fast the server answers. Each check says why it matters and how to fix it.

      How the score works

      Every check has a weight: the ones that decide whether a page can be found at all (it loads, it is allowed to be indexed, robots.txt lets Google in, it has a title) count the most; nice-to-haves such as a favicon or HSTS count a little. A pass earns the full weight, a warning half, a fail nothing. If the page cannot be indexed at all (an error status, noindex, or blocked by robots.txt) the score is capped at 30, because nothing else matters until that is fixed.

      Questions

      Will a high score put my page first on Google?
      No. These are the technical basics that let search engines read and show the page well. Ranking mostly depends on whether the page answers what people search for, and on other sites linking to it.
      Why does my title look cut off in the preview?
      Google cuts titles by width in pixels (about 580 on a computer), not by a fixed number of letters, so "WWW" uses more room than "iii". The preview measures the text the same way. Google also rewrites titles and descriptions it thinks do not match the page, so the real result can differ.
      Is the speed number a full speed test?
      No: it is only how long the server took to start sending the HTML to our checker. Use the PageSpeed Insights link for the real loading speed and Core Web Vitals on phones.
      Why does it say "Not found in the sitemap"?
      The checker reads the sitemaps named in robots.txt (or /sitemap.xml) and up to three of the sitemap files a sitemap index points to, and looks for this exact address or its canonical. On very big sites the page may be in a sitemap file it did not open; the result then says how many were checked.
      Does it see content added by JavaScript?
      No. It reads the HTML the server sends, like the first pass of a search engine. Google runs JavaScript later, but text that only appears after scripts run is found more slowly, and other search engines and social sites may never see it.
      What is sent and stored?
      The address you type goes to mes.fm's server, which fetches that one page plus robots.txt and the sitemap, and returns the findings to your browser. Results may be cached for ten minutes so a repeated check is fast; nothing is saved with your name. Your recent checks are kept only in this browser. Private addresses, IP numbers and local names are refused.
