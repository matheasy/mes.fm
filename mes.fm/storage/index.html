What about the free space on my disk?

A web page can't see how full your disk is. Browsers do offer navigator.storage.estimate(), but that number is something else: it is how much this browser lets websites store (their quota), not your disk's free space. Here it is, for the curious:

To see real disk space: Windows: File Explorer > This PC. Mac: Apple menu > System Settings > General > Storage. Linux: df -h. Android: Settings > Storage.

A free disk usage analyzer that runs in your browser

MES Storage Analyzer is like WinDirStat, DaisyDisk, GrandPerspective or WizTree, with nothing to install. Pick a folder (Documents, Downloads, a project folder, an external drive) and see at a glance what is taking up the space: a sunburst chart with rings of folders (DaisyDisk style), a treemap where every file is a rectangle sized by its size (WinDirStat style), a sortable folder table, the 50 largest files, totals by file type, old and large files, possible duplicates and empty folders.

What a browser can and can't do

It sees only the folder you pick
Web pages can't look at your whole disk. You choose one folder and the page gets read-only access to it, for this tab only.
No system folders
Browsers refuse to open the top of the disk, your home folder itself, and system folders like Windows or /System. Pick a folder inside them instead (Documents, Downloads, Pictures, a drive's folder).
It doesn't read your files
Sizes and dates come from the file list, like a file manager's. The one exception is the duplicate check, which reads the files you ask it to compare (and still uploads nothing).
No "Show in Finder / Explorer"
A web page isn't allowed to open your file manager or point at a file there. Use "Copy path" and paste it into your file manager's address bar or search.
No delete button, on purpose
Some browsers could let a page delete files in a folder you opened, but deleting from a web page skips the Recycle Bin / Trash, so a slip can't be undone. Delete in your file manager, where it goes to the bin first.
No free-space number
The disk's size and free space aren't available to web pages. The storage quota a browser reports is for website data, not your disk.

Which browsers work

Chrome, Edge, Opera and other Chromium browsers on a computer use the File System Access API: the scan runs in the background (a Web Worker), shows empty folders and works with very large folders. Firefox, Safari and Brave use the browser's "upload a folder" picker instead: nothing is uploaded, but the browser may say "upload" in its window, it shows a list of the files first, and empty folders don't appear. In Brave, the faster way is off by default: type brave://flags/#file-system-access-api in the address bar, set it to Enabled and restart Brave. On iPhone and iPad Safari can't open folders, so use a computer. You can also drag a folder onto this page.

Questions

Why is the total smaller than my file manager says?

This page adds up file sizes. Disks store files in blocks, so a file uses a little more space on disk than its size, especially many small files. Folders you can't read, hidden system files and files in other folders (like caches outside the one you picked) aren't counted either. Sizes use 1 KB = 1,000 bytes, as macOS does; Windows shows 1 KB = 1,024 bytes, so its numbers look about 7% smaller in GB.

What counts as old?

"Last changed" is the date the file was last modified. Web pages can't see when a file was last opened, so an old date means "not changed", not necessarily "not used".

How are duplicates found?

First by size: files with exactly the same number of bytes are possible duplicates, which costs nothing. If you press "Check contents", the page reads those files and compares their SHA-256 fingerprints; files with the same fingerprint have the same contents. Very large files (over 2 GB) are compared by their first and last 8 MB and are marked as "probably the same".

What about shortcuts and links?

Browsers decide how links (symlinks, shortcuts, aliases) appear; some are skipped and a shortcut file counts as a small file. A link loop can't run forever: the scan stops 64 folder levels down and lists anything it skipped under "Couldn't read".

How many files can it handle?

Hundreds of thousands. The scan keeps the list in compact arrays, and the charts only draw what is big enough to see. A folder with a million files works too but needs a good amount of memory.
